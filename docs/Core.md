# Magic Compact Core

Source of truth for Magic Compact behavior and safety guarantees.

## Goal

Compress a conversation without flattening it into a single generic recap.

## Core Behavior

- `/magic-compact [N]` compacts the current conversation in place.
- `N` keeps the most recent eligible assistant turns unchanged. Default: `0`.
- We also provide `/magic-trim [N]`, which applies tool I/O trimming without summarizing assistant turns.
- The plugin creates a backup before mutating the conversation.
- User-authored message parts are preserved exactly. Original user file parts and assistant inline image file parts covered by an accepted v3 manifest are never updated, deleted, moved to omission storage, or replaced in persistence, backups, API responses, or exports.
- Older assistant turns are replaced turn-by-turn with validated continuation summaries, not merged into one blob.
- Compaction creates exactly one ephemeral fork of the complete source session and makes exactly one summarizer request for all summary-free selected turns. The fork is changed to a deny-all permission ruleset before prompting. The request always uses the hidden Magic summarizer agent and the explicit model and variant configured on OpenCode's native hidden compaction agent; the source session model is never a fallback.
- After the deny-all update, Magic Compact loads the fork, verifies its chronological message/part-type and turn shape against the source plan despite rewritten IDs, and chooses a crypto-quality 128-bit generation nonce absent from every ordinary string in both the source snapshot and rewritten fork history. It injects a synthetic Magic-owned nonce-and-ordinal marker into the first user message of each selected fork turn plus an optional nonce-bound stop marker. Collision retries are bounded and fail closed. These markers exist only in the ephemeral fork. The explicit prompt is a bounded turn index containing each exact marker, monotonic ordinal, exact escaped first ordinary non-synthetic/non-ignored user text line capped at 300 characters, and expected inline-image count. SDK objects, source refs, assistant traces, tool states, data URLs, provider metadata, encrypted reasoning, and manual file parts never enter the explicit prompt.
- OpenCode supplies the complete forked user, assistant, tool, and media history through its native model conversion. User files become typed file content; completed tool `state.output` becomes tool-result text/content and tool `state.attachments` become typed media/file content. Magic Compact does not serialize, redact, reattach, fetch, resize, OCR, or chunk media for generation.
- One JSON response contains one object per indexed turn in exact ordinal order. Every object must echo its exact marker token, ordinal, and anchor and include a nonempty summary. Turns with authoritative source user or assistant inline images must include exactly one nonempty visual description per image ordinal. Missing, stale, spoofed, shifted, duplicate, reordered, or empty values fail before backup or source mutation. A summary or visual description containing the active exact generation nonce or marker token also fails before framing; unrelated nonce-shaped text remains valid. Only the active exact generation nonce or marker token is forbidden inside summaries and visual descriptions; marker nonces are validation-only and never persist in visible summary text, and useful source identifiers may remain when the model includes them.
- Accepted v3 summaries persist a version-1 manifest built locally from authoritative source user then assistant inline image parts, binding stable encounter ordinal, exact MIME, and SHA-256 of the exact original URL. Tool `state.attachments` remain native tool media and never enter this persisted manifest. OpenCode's `experimental.chat.messages.transform` hook applies one pure projection that validates every manifest-covered historical image by canonical ordinal/MIME/hash and replaces it with a lightweight declarative text placeholder only when the placeholder's canonical token count is strictly smaller than the original file URL token contribution; otherwise the exact file part stays inline and model-facing. Persisted v2 manifests remain user-only and supported, but their stored `partId` is compatibility data and does not block a content-identical fork or recovered backup with rewritten IDs. Missing manifests are inert; missing/added/reordered images, malformed manifests, MIME changes, or URL-hash changes fail closed instead of hiding or silently resending changed media. Because every replacement strictly reduces canonical tokens, projected media token counts are non-negative by construction.
- Useful tool calls stay visible; bulky tool I/O is replaced with retrievable omission records.
- Omitted bytes are returned only when OpenCode can authorize the current session and prove cache integrity; unavailable or ambiguous historical entries fail closed.
- Any turn containing an existing Magic summary part is opaque persisted data for the compaction writer. V0, v1, and v2 turns are skipped message- and part-identically, while the normal boundary allows newer turns to compact safely. `/magic-trim` leaves the summary parts themselves unchanged. New summaries use the versioned v3 part ID namespace only on summary-free turns.
- During `/magic-compact`, a completed OpenCode-native checkpoint owns an immutable durable prefix. Compaction processes only completed turns after that checkpoint summary.
- If the native checkpoint leaves no eligible turns, compaction is a no-op and creates no backup or summary request.
- Before backup or source mutation, Magic Compact projects the complete canonical model-facing result with local `gpt-tokenizer` counting and the same pure media-manifest projection used by the OpenCode hook. Model-facing synthetic content is included; ignored user reporting notices are excluded; ignored assistant text stays in the active count and source projection. Attempts below 20% of eligible removable tokens, subject to a small absolute floor, fail unchanged with a content-free failure message.
- A planned turn is replaced only when its exact projected canonical active token count, after injecting its summary and applying the same planned pruning, is strictly lower than its exact source canonical active token count. Rejected turns stay message- and part-identical: no summary is injected and no pruning is applied to them. The aggregate savings gate evaluates the eligible token base over only the selected profitable turns, and its projected savings already net out the fixed model-facing boundary.
- `/magic-stats` shows cumulative savings for the current conversation.
- `read_omitted_content` retrieves omitted tool content by Content ID.

## Safety

- If compaction fails, the attempt aborts. The provider model request has no local wall-clock deadline and is awaited normally. Provider rejection, cancellation, or response validation failure attempts `session.abort`, and the generation fork is deleted afterward. Fork creation, permission update, abort, deletion, and every Magic Compact toast use a 30-second control-operation deadline; a notification timeout or failure never replaces or delays the command's primary outcome. A timed-out fork creation that later fulfills receives detached best-effort bounded abort then deletion. Surfaced lifecycle errors contain only fixed stage/kind text, the source session ID, and a range-validated HTTP status; raw provider/control/model messages, bodies, prompts, history, and response output are discarded.
- Before fork creation, Magic Compact scans the complete source history that may reach the fork, including retained and opaque summary-bearing turns, for image-bearing user or assistant file parts and tool `state.attachments`. If any image may be model-visible, the configured compaction model must resolve in the provider catalog with `capabilities.input.image === true`. If OpenCode's native fork request reports a safe context-window, prompt-too-long, input-too-long, or HTTP 413 category, fail with guidance to run `/magic-trim` first and retry. If provider error or finish metadata reports output-length or max-token exhaustion, fail with guidance to increase `N` so fewer turns are selected. Raw provider text is never surfaced. Do not add per-turn fallback, chunk summaries, retries, model fallback, or partial source mutation.
- Malformed authoritative user or assistant inline-image data, missing or misordered visual descriptions, projection mismatch, and every other media validation failure occur before backup/source mutation/success stats. No media path falls back to another model or provider.
- From the first source-write attempt onward, automatic rollback is disabled and both source and backup are preserved. The backup is created only after the full projection and profitability gates pass, and every failure after backup creation preserves both sessions for manual recovery.
- Cache-read diagnostics must not expose local filesystem or session paths. Integrity diagnostics may retain path-free validation detail.
- During `/magic-compact`, malformed, ambiguous, dangling, or active incomplete native checkpoint state, and behavior-affecting drift detected by pre-write revalidation, fail before summary, boundary, or pruning writes. An older incomplete or ambiguous marker may remain only when its complete ambiguous or incomplete artifact set lies wholly before a later valid checkpoint marker and is inside that checkpoint's frozen prefix.
- After owned summary and boundary insertion, Magic Compact reloads the full source and requires the original snapshot plus exactly those insertions. Any unexpected added, missing, changed, or reordered message or part preserves both the live source and backup without selecting or deleting either, before a planned prune mutation, omission commit, stats write, or source metadata update. The surfaced content-free error names both session IDs for manual recovery.
- Preserve-both recovery applies to pre-write source drift detected after backup creation and every failure after the first source-write attempt, including summary or boundary insertion, post-insertion validation, pruning, metadata, notice, final projection, and stats persistence. Concurrent messages remain in the live source, and no failed attempt records a successful stats increment.
- Prompt instructions require each summary to remain readable and continuation-focused: preserve the outcome, important process and decisions, verification, and unresolved or next work when present. The host validates only the small structural response contract, not brittle semantic status, evidence, ref, current-state, preserve-mode, or visible-scaffolding protocols.

## Stats

- Track net tokens physically pruned, inline-image tokens projected out per model request, their separate cached-read savings, and estimated money saved per conversation. Existing version-1 stats without media fields remain valid and read as zero media savings. Before, projected-after, and actual-after model-facing counts use the same pure media projection plus local `gpt-tokenizer` canonical active-content method: model-facing synthetic parts are included and ignored reporting notices are excluded. Compaction and trim compute the exact pre-notice active result once, persist savings on that basis, inject an ignored notice that explicitly says it is excluded, and require the final actual active count to equal the projection. There is no self-referential fixed point. Every notice distinguishes this estimate from provider context-window usage. OpenCode's context meter is a provider usage snapshot and can remain stale after in-place compaction until a later assistant response refreshes it. Magic Compact never fabricates an after-provider count or mutates provider token metadata.
