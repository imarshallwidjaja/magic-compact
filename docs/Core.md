# Magic Compact Core

Source of truth for Magic Compact behavior and safety guarantees.

## Goal

Compress a conversation without flattening it into a single generic recap.

## Core Behavior

- `/magic-compact [N]` compacts the current conversation in place.
- `N` keeps the most recent eligible assistant turns unchanged. Default: `0`.
- We also provide `/magic-trim [N]`, which applies tool I/O trimming without summarizing assistant turns.
- The plugin creates a backup before mutating the conversation.
- User messages are preserved exactly.
- Older assistant turns are summarized turn-by-turn, not merged into one blob.
- The bounded historical evidence supplied to each scratch session is authoritative for summaries; summaries never inspect external state or continue unfinished work.
- Useful tool calls stay visible; bulky tool I/O is replaced with retrievable omission records.
- Omitted bytes are returned only when OpenCode can authorize the current session and prove cache integrity; unavailable or ambiguous historical entries fail closed.
- Re-running compaction later preserves earlier summaries, including existing unversioned v0 summary parts, and compacts newer turns. `/magic-trim` also leaves those summary parts unchanged.
- During `/magic-compact`, a completed OpenCode-native checkpoint owns an immutable durable prefix. Compaction processes only completed turns after that checkpoint summary.
- If the native checkpoint leaves no eligible turns, compaction is a no-op and creates no backup or summary request.
- Large completed turns remain model-eligible regardless of serialized size, message count, or tool count. A turn is deterministic-only when tool state, assistant-message metadata, or historical evidence is failed, not-run, running, error, unknown, incomplete, or otherwise unresolved. A later successful assistant message resolves an earlier assistant-message error for routing while retaining bounded recovered-error evidence.
- Model summaries run in transcript-free scratch sessions from bounded exact per-turn evidence maps. Scratch sessions have no parent, deny all tools and side effects, and run at most two requests concurrently.
- Before backup or source mutation, Magic Compact projects the complete canonical active result with local `gpt-tokenizer` counting. Model-facing synthetic content is included; ignored user reporting notices are excluded; ignored assistant text stays in the active count, exact evidence, and post-prune summaries. Attempts below 20% of eligible removable tokens, subject to a small absolute floor, fail unchanged with a content-free failure message.
- A planned turn is replaced only when its exact projected canonical active token count, after injecting its summary and applying the same planned pruning, is strictly lower than its exact source canonical active token count. Rejected turns stay message- and part-identical: no summary is injected and no pruning is applied to them. The aggregate savings gate evaluates the eligible token base over only the selected profitable turns, and its projected savings already net out the fixed model-facing boundary.
- `/magic-stats` shows cumulative savings for the current conversation.
- `read_omitted_content` retrieves omitted tool content by Content ID.

## Safety

- If compaction fails, the attempt aborts.
- If a backup exists, it is used for recovery.
- Cache-read diagnostics must not expose local filesystem or session paths. Integrity diagnostics may retain path-free validation detail.
- During `/magic-compact`, malformed, ambiguous, dangling, or active incomplete native checkpoint state, and any concurrent behavior-affecting source message or part drift, fails before summary, boundary, or pruning writes. An older incomplete or ambiguous marker may remain only when its complete artifact set is wholly before a later valid checkpoint marker and therefore inside that checkpoint's frozen prefix.
- Scratch sessions have no parent transcript or inherited checkpoint artifact. Preserve-both recovery remains reserved for durable source drift, including a final actual-versus-projected token mismatch after source writes, or source state that cannot be confirmed unchanged. Detected late drift preserves the partially mutated source and backup and records no successful stats increment.
- Standard summary batches require exactly one plain-text JSON object keyed by the exact assistant turn IDs, with one narrative body per value. The summarizer-scoped `chat.params` hook best-effort clamps provider generation to at most 4,000 output tokens when OpenCode supplies a compatible active limit, never synthesizes a limit providers reject, and leaves other agents unchanged; Magic Compact independently parses collected text parts with `JSON.parse` and validates transport shape, exact keys, string values, substantive content, placeholders, raw closed-schema machine evidence/internal accounting, unsafe C0/C1 and bidi presentation controls, unpaired UTF-16 surrogates, and the same unconditional 4K local-token response cap before folding presentation. The host classifies each accepted standard turn, folds CRLF, LF, CR, vertical tab, form feed, NEL, U+2028, and U+2029 boundaries into one narrative line, neutralizes raw `&` as `&amp;` before raw `<` as `&lt;`, and persists exactly `Outcome: <host outcome>\nWork: <narrative>`. A local invariant requires those two physical lines, substantive work, and no alternate separator, unsafe control, unpaired surrogate, raw `<`, or ampersand outside the host escapes; final token and profitability projection uses that rendered capsule. Deterministic `partial` turns keep their existing model-free renderer. One failed batch may be retried once in a fresh scratch session only for a typed content-free summary-contract failure and only after failed-session cleanup succeeds; provider, authentication, context, body-info, SDK, cancellation, timeout, and cleanup failures are not retried. Timeout or client cancellation explicitly awaits server-side `session.abort` before scratch deletion, preserving prompt, abort, and deletion failures together.
- A generated summary must preserve evidenced continuation state. Deterministic-only summaries render model-free, human-readable continuation capsules (Outcome, Work, Verification, VCS, Unresolved, and Next) from the same classification evidence. The existing 2,048-token cap and 512-token optional allowance are safety ceilings, not output targets. Every substantive text part in the final assistant message forms one ordered final response, retained in full when it fits the remaining capsule budget. Otherwise every classified decision, verification, VCS, unresolved, and next-action fact from any of those parts is retained through source-anchored readable excerpts. Decisive failed, not-run, running, error, unknown, incomplete, credentials-missing, could-not-finish, blocked, and unresolved state routes deterministically. Only genuinely equivalent normalized unresolved facts aggregate, with truthful counts; every distinct actionable payload remains visible while it fits, and an overflow of distinct required facts fails closed before backup or mutation. Visible capsules contain no standalone raw evidence records, source windows, or internal record accounting, while legitimate technical prose that mentions field syntax remains valid. Underlying error tool parts remain active, so capsules do not duplicate their full I/O. All summaries and projected pruning remain in memory until full source revalidation and the useful-savings gate pass.

## Stats

- Track tokens pruned, cached-read tokens saved, and estimated money saved per conversation. Before, projected-after, and actual-after counts use the same local `gpt-tokenizer` canonical active-content method: model-facing synthetic parts are included and ignored reporting notices are excluded. Compaction and trim compute the exact pre-notice active result once, persist savings on that basis, inject an ignored notice that explicitly says it is excluded, and require the final actual active count to equal the projection. There is no self-referential fixed point. Every notice distinguishes this estimate from provider context-window usage. OpenCode's context meter is a provider usage snapshot and can remain stale after in-place compaction until a later assistant response refreshes it. Magic Compact never fabricates an after-provider count or mutates provider token metadata.
