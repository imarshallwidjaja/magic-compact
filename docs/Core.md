# Magic Compact Core

Source of truth for Magic Compact behavior and safety guarantees.

## Goal

Compress a conversation without flattening it into a single generic recap.

## Core Behavior

- `/magic-compact [N]` compacts the current conversation in place.
- `N` keeps the most recent eligible assistant turns unchanged. Default: `0`.
- We also provide `/magic-trim [N]`, which applies tool I/O trimming without summarizing assistant turns.
- The plugin creates a backup before mutating the conversation.
- User-authored message parts are preserved exactly. Original user file parts and assistant inline image file parts covered by an accepted v3 manifest are never updated, deleted, moved to omission storage, or replaced in persistence, backups, API responses, or exports.
- Older assistant turns are replaced turn-by-turn with validated continuation summaries, not merged into one blob.
- Compaction resolves the explicit model and variant configured on OpenCode's native hidden compaction agent and the matching live provider descriptor once; the source session model is never a fallback. The output target is `min(32K, floor(model output * 0.5))`, usable input is `min(model input when present, context - output target)`, the normal target is `min(400K, floor(usable input * 0.8))`, and the hard single-turn limit is `floor(usable input * 0.9)`. Every batch reserves 8K only for non-explicit host, system, and provider overhead. It separately tokenizes the complete rendered explicit request exactly once, including static instructions, the repeated global index, target JSON and punctuation, conservative marker and marker-injection text, exact ordinals and 300-code-point anchors, media counts, and any following-halo stop record. Batches carry at most 32 target turns.
- Ordinary model-visible text and reasoning are estimated with the local tokenizer without serializing SDK message objects. Image/PDF-typed file parts and completed non-compacted tool `state.attachments` receive fixed 8K media charges; `text/plain` and directory file parts are non-model-visible and carry no charge, and other model-visible file parts and attachments are estimated by their URL (encoded length for `data:` URLs, tokenized text otherwise). Arbitrary or nested `data:` strings in tool input, completed output, errors, and model-visible interrupted `state.metadata.output` remain ordinary provider-request text and are estimated conservatively by encoded length without invoking the tokenizer on their payloads. Compacted tool output becomes OpenCode's fixed cleared-result text with no attachments; other error, interrupted, pending, and running states mirror the pinned native conversion. Output packing adds estimated summary and visual-description content to the mandatory JSON envelope/array/object punctuation, echoed marker/ordinal/anchor fields, `summary` property, and every visual-description ordinal/description record. Candidates are partitioned chronologically into contiguous batches without splitting or bin-packing turns. A turn above the normal target receives a dedicated batch if it fits the hard limit; an impossible turn fails before backup with `/magic-trim`-first guidance.
- Before batching, Magic Compact derives one immutable `globalTurnIndex` from every complete turn in the effective source history after the newest native checkpoint. It includes target, opaque existing-summary, and retained-tail turns; excludes an active incomplete turn; and gives each entry only `{sourceOrdinal, anchor}`, where `sourceOrdinal` is the stable one-based position in complete source-turn order and `anchor` is the first ordinary user line capped at 160 characters.
- Each batch creates a fresh ephemeral fork of the complete source under the control deadline and changes it to deny-all permissions. Magic Compact verifies rewritten IDs and chronological role/part-type shape, retains only complete target turns plus at most one complete neighboring non-checkpoint turn on each side while native history plus the complete explicit request, including an optional following-halo stop record and marker, stays within `min(500K, floor(usable input * 0.9))`, and captures the retained rewritten message IDs, part IDs, order, roles, parent links, part types, and fork-scoped references before deleting every other fork message sequentially through `session.deleteMessage`. It never deletes individual parts for generation isolation. The reload must match that exact retained identity before unique nonce-bound target markers and an optional following-halo stop marker are inserted.
- OpenCode supplies retained fork user, assistant, tool, reasoning, and media history through native model conversion. Every prompt receives the byte-identical global orientation map plus a separate exact target index of marker, target ordinal, 300-character anchor, and expected inline-image count. The global map gives long-range user-anchor orientation but no distant detailed assistant/tool history. SDK objects, source refs, assistant traces, tool states, data URLs, provider metadata, encrypted reasoning, and manual file parts never enter either index.
- One JSON response per batch contains one object per indexed target in exact target-ordinal order. Its mandatory envelope and every echoed marker, ordinal, exact anchor, `summary` field, and visual-description record are included in output packing before estimated content. Every object must echo its exact marker token, target ordinal, and target anchor and include a nonempty summary plus exact visual coverage. Missing, stale, spoofed, shifted, duplicate, reordered, empty, or active-nonce values fail before backup or source mutation. All batch results and exact target-ordinal coverage are validated atomically before any durable write.
- Accepted v3 summaries persist a version-1 manifest built locally from authoritative source user then assistant inline image parts, binding stable encounter ordinal, exact MIME, and SHA-256 of the exact original URL. Tool `state.attachments` remain native tool media and never enter this persisted manifest. OpenCode's `experimental.chat.messages.transform` hook applies one pure projection that validates every manifest-covered historical image by canonical ordinal/MIME/hash and replaces it with a lightweight declarative text placeholder only when the placeholder's canonical token count is strictly smaller than the original file URL token contribution; otherwise the exact file part stays inline and model-facing. Persisted v2 manifests remain user-only and supported, but their stored `partId` is compatibility data and does not block a content-identical fork or recovered backup with rewritten IDs. Missing manifests are inert; missing/added/reordered images, malformed manifests, MIME changes, or URL-hash changes fail closed instead of hiding or silently resending changed media. Because every replacement strictly reduces canonical tokens, projected media token counts are non-negative by construction.
- Useful tool calls stay visible; bulky tool I/O is replaced with retrievable omission records.
- Omitted bytes are returned only when OpenCode can authorize the current session and prove cache integrity; unavailable or ambiguous historical entries fail closed.
- Any turn containing an existing Magic summary part is opaque persisted data for the compaction writer. V0, v1, and v2 turns are skipped message- and part-identically, while the normal boundary allows newer turns to compact safely. `/magic-trim` leaves the summary parts themselves unchanged. New summaries use the versioned v3 part ID namespace only on summary-free turns.
- During `/magic-compact`, a completed OpenCode-native checkpoint owns an immutable durable prefix. Compaction processes only completed turns after that checkpoint summary.
- If the native checkpoint leaves no eligible turns, compaction is a no-op and creates no backup or summary request.
- Before backup or source mutation, Magic Compact projects the complete canonical model-facing result with local `gpt-tokenizer` counting and the same pure media-manifest projection used by the OpenCode hook. Model-facing synthetic content is included; ignored user reporting notices are excluded; ignored assistant text stays in the active count and source projection. Attempts below 20% of eligible removable tokens, subject to a small absolute floor, fail unchanged with a content-free failure message.
- A planned turn is replaced only when its exact projected canonical active token count, after injecting its summary and applying the same planned pruning, is strictly lower than its exact source canonical active token count. Rejected turns stay message- and part-identical: no summary is injected and no pruning is applied to them. The aggregate savings gate evaluates the eligible token base over only the selected profitable turns, and its projected savings already net out the fixed model-facing boundary.
- `/magic-stats` shows cumulative savings for the current conversation.
- `read_omitted_content` retrieves omitted tool content by Content ID.

## Safety

- Independent batches run with a maximum concurrency of five. Every prompt, index, fork isolation plan, and estimate derives from the same pre-generation source; generated summaries never feed another batch. Provider requests have no local wall-clock deadline. Fork creation, permission update, message deletion/reload, marker insertion, abort, deletion, and every toast use the 30-second control-operation deadline. A timed-out fork creation that later fulfills receives detached bounded abort/delete cleanup. The first provider, throttling, validation, lifecycle, or cleanup failure stops new admission; every already-active batch is drained and every active failure is collected in deterministic batch order. One sanitized error or sanitized aggregate is thrown, every generated result is discarded, and source, backup, and stats stay unchanged because generation completes before backup creation. No request is retried and no partial batch result is accepted.
- The image capability gate covers content retained by any planned fork. Native context overflow reports `/magic-trim`-first guidance. A configured model input budget too small to fit the fixed 8K non-explicit host reserve, or too small for that reserve plus the complete explicit request and mandatory global index, fails before any fork with concise trim-first/model-capacity guidance. Planning uses a fixed-shape conservative nonce; each real nonce and exact immutable prompt are rendered and checked against the recorded estimate plus normal, hard, halo, usable-input, and output limits before fork creation. Single-turn output exhaustion requires a compaction model with more output capacity; multi-turn output exhaustion reports larger-`N` guidance. Raw provider/control/model messages, bodies, prompts, histories, output, and aggregate causes are never surfaced. Do not add adaptive retries, per-turn fallback, alternate models, or partial source mutation.
- Malformed authoritative user or assistant inline-image data, missing or misordered visual descriptions, projection mismatch, and every other media validation failure occur before backup/source mutation/success stats. No media path falls back to another model or provider.
- From the first source-write attempt onward, automatic rollback is disabled and both source and backup are preserved. The backup is created only after the full projection and profitability gates pass, and every failure after backup creation preserves both sessions for manual recovery.
- `/magic-compact` fails closed when the source session has a pending OpenCode revert before generation, and rechecks immediately before the first source write. Any OpenCode `session.prompt` applies hidden destructive revert cleanup that deletes the reverted suffix, so compaction refuses to write to such a session rather than losing the suffix. Magic Compact never forces the cleanup itself: OpenCode exposes no session-serialized or compare-and-swap revert commit, and forcing cleanup could delete concurrently appended messages. Users resolve the pending revert themselves before retrying — `/redo` restores the undone content without a model call, or a normal OpenCode prompt commits the discard.
- Cache-read diagnostics must not expose local filesystem or session paths. Integrity diagnostics may retain path-free validation detail.
- During `/magic-compact`, malformed, ambiguous, dangling, or active incomplete native checkpoint state, and behavior-affecting drift detected by pre-write revalidation, fail before summary, boundary, or pruning writes. An older incomplete or ambiguous marker may remain only when its complete ambiguous or incomplete artifact set lies wholly before a later valid checkpoint marker and is inside that checkpoint's frozen prefix.
- After owned summary and boundary insertion, Magic Compact reloads the full source and requires the original snapshot plus exactly those insertions. Any unexpected added, missing, changed, or reordered message or part preserves both the live source and backup without selecting or deleting either, before a planned prune mutation, omission commit, stats write, or source metadata update. The surfaced content-free error names both session IDs for manual recovery.
- Preserve-both recovery applies to pre-write source drift detected after backup creation and every failure after the first source-write attempt, including summary or boundary insertion, post-insertion validation, pruning, metadata, notice, final projection, and stats persistence. Concurrent messages remain in the live source, and no failed attempt records a successful stats increment.
- Prompt instructions require each summary to remain readable and continuation-focused: preserve the outcome, important process and decisions, verification, and unresolved or next work when present. The host validates only the small structural response contract, not brittle semantic status, evidence, ref, current-state, preserve-mode, or visible-scaffolding protocols.

## Stats

- Track net tokens physically pruned, inline-image tokens projected out per model request, their separate cached-read savings, and estimated money saved per conversation. Existing version-1 stats without media fields remain valid and read as zero media savings. Before, projected-after, and actual-after model-facing counts use the same pure media projection plus local `gpt-tokenizer` canonical active-content method: model-facing synthetic parts are included and ignored reporting notices are excluded. Compaction and trim compute the exact pre-notice active result once, persist savings on that basis, inject a concise ignored notice reporting the exact pre-notice before/after context counts, the trimmed amount and percentage, and the operation kind (summarized assistant turns or trimmed tool calls), and require the final actual active count to equal the projection. There is no self-referential fixed point. The `/magic-stats` notice continues to distinguish canonical estimates from provider context-window usage; compact and trim notices report only canonical counts. OpenCode's context meter is a provider usage snapshot and can remain stale after in-place compaction until a later assistant response refreshes it. Magic Compact never fabricates an after-provider count or mutates provider token metadata.
