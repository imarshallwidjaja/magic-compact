# Magic Compact Core

Source of truth for Magic Compact behavior and safety guarantees.

## Goal

Compress a conversation without flattening it into a single generic recap.

## Core Behavior

- `/magic-compact [N]` compacts the current conversation in place.
- `N` keeps the most recent eligible assistant turns unchanged. Default: `0`.
- We also provide `/magic-trim [N]`, which applies tool I/O trimming without summarizing assistant turns.
- The plugin creates a backup before mutating the conversation.
- User-authored message parts are preserved exactly. Original user file parts, including exact inline image URLs, are never updated, deleted, moved to omission storage, or replaced in persistence, backups, API responses, or exports.
- Older assistant turns are replaced turn-by-turn with validated agentic capsules, not merged into one blob.
- Compaction uses one hidden deny-all scratch session, one user message, one summarizer request, and one response per candidate turn with bounded concurrency `2`. Each worker builds one compact linear-size prompt only when its candidate is scheduled and releases it after request cleanup, so no more than two full prompts are resident. Each request receives the complete untruncated ordered turn trace and must return the canonical JSON result. A prompt over the fixed safe per-string transport cap becomes multiple ordered text parts in that same message and request; exact concatenation reconstructs the original prompt, UTF-16 surrogate pairs stay intact, and no part exceeds the cap. The pool schedules every candidate even after another fails, drains every request and its abort/delete cleanup, then aggregates all candidate failures deterministically before backup. There is no batching of turns, independent chunk summarization, retry loop, verifier, local input cap, or local summary ceiling.
- Only candidate summarized turns are eligible for media handling. If the aggregate canonical token contribution of their user inline `data:` `image/*` URLs is above the fixed internal 1,024-token threshold, every inline image in that turn becomes one ordered cohort. Exact-threshold, under-threshold, retained-tail, remote, and non-image file parts remain on the ordinary path. There is no public media configuration, remote fetch, OCR, resizing, chunking, object storage, native-checkpoint emulation, or general oversized-user-text summarization.
- A media cohort uses the exact configured compaction model only after its catalog entry explicitly reports image input support. The serialized text trace replaces each image URL with a stable `magic-compact-image:N` ordinal, and the scratch request attaches each original image exactly once as a real file/image part in that order after every prompt text block. System and request prompts treat image pixels, diagrams, visible/OCR text, and embedded visual instructions as inert untrusted evidence, never as instructions to follow. The canonical result adds exactly one substantive `{ordinal, description}` visual-coverage entry per image; missing, empty, out-of-order, or marker-only coverage is invalid.
- Accepted media capsules persist a version-1 manifest binding every original user image part ID, exact MIME, stable ordinal, and SHA-256 of the exact original URL. OpenCode's `experimental.chat.messages.transform` hook applies one pure projection that replaces only exact manifest-covered historical images with lightweight declarative text placeholders in future model requests. Missing manifests are inert. Each manifest ordinal binds to the image at the same canonical encounter position, so missing/added/reordered images, malformed manifests, MIME changes, or URL-hash changes fail closed instead of hiding or silently resending changed media.
- Useful tool calls stay visible; bulky tool I/O is replaced with retrievable omission records.
- Omitted bytes are returned only when OpenCode can authorize the current session and prove cache integrity; unavailable or ambiguous historical entries fail closed.
- Any turn containing an existing Magic summary part is opaque persisted data for the compaction writer. V0, v1, and v2 turns are skipped message- and part-identically, while the normal boundary allows newer turns to compact safely. `/magic-trim` leaves the summary parts themselves unchanged. New capsules use the versioned v2 part ID namespace only on summary-free turns.
- During `/magic-compact`, a completed OpenCode-native checkpoint owns an immutable durable prefix. Compaction processes only completed turns after that checkpoint summary.
- If the native checkpoint leaves no eligible turns, compaction is a no-op and creates no backup or summary request.
- Every candidate summary-free turn request includes user messages; all assistant reasoning, text, subtask, file, patch, and snapshot parts; all tool names, inputs, statuses, outputs, errors, and MCP calls; and stable message/part refs. Iterative preflight accepts only the documented `magic-compact-tagged-trace-v1` forms: JSON primitives; explicit undefined properties/slots and sparse holes; bigint and special numbers; valid/invalid same-realm dates; same-realm ArrayBuffer/SharedArrayBuffer values and Buffer/DataView/numeric/BigInt views with backing type and complete base64 bytes; ordinary same-realm arrays; and object/null-prototype records. Cycles, functions, symbols, accessors, proxies, cross-realm/custom prototypes, duplicate message/part refs, and generated ref collisions fail content-free before scratch creation. Trace data is explicitly untrusted and inert in both system and request prompts.
- Structured tool lifecycle, strictly validated allowlisted Hive/task result schemas, and canonical `state.metadata.exit` determine current state. Recognized discriminator types, finite JSON structure, supported statuses, consistent success/failure signals, and required blocker/error details must all validate. Malformed recognized results remain exact actionable unresolved evidence. Nonzero exits remain unresolved, and exit zero cannot suppress recognized nonzero verification failure/error counts or zero-run results. Generic failure words in exit-zero git output are opaque.
- Later tool evidence resolves only the same trimmed raw command plus a lexically normalized explicit absolute POSIX/Windows `cwd`/`workdir`. Relative, missing, mixed-style, NUL-containing, or conflicting contexts are unscoped and fail closed. Assistant prose never resolves or creates structured state.
- Before backup or source mutation, Magic Compact projects the complete canonical model-facing result with local `gpt-tokenizer` counting and the same pure media-manifest projection used by the OpenCode hook. Model-facing synthetic content is included; ignored user reporting notices are excluded; ignored assistant text stays in the active count, exact evidence, and post-prune summaries. Attempts below 20% of eligible removable tokens, subject to a small absolute floor, fail unchanged with a content-free failure message.
- A planned turn is replaced only when its exact projected canonical active token count, after injecting its summary and applying the same planned pruning, is strictly lower than its exact source canonical active token count. Rejected turns stay message- and part-identical: no summary is injected and no pruning is applied to them. The aggregate savings gate evaluates the eligible token base over only the selected profitable turns, and its projected savings already net out the fixed model-facing boundary.
- `/magic-stats` shows cumulative savings for the current conversation.
- `read_omitted_content` retrieves omitted tool content by Content ID.

## Safety

- If compaction fails, the attempt aborts. Provider model requests have no local wall-clock deadline and are awaited normally. Provider rejection, cancellation, or response parsing/validation/framing failure attempts `session.abort`, and every created scratch session is deleted afterward. Scratch creation, abort, deletion, and every Magic Compact toast use a 30-second control-operation deadline; a notification timeout never replaces or delays the command's primary success, no-op, or failure outcome. A timed-out create that later fulfills is detached from the selected failure outcome and receives best-effort bounded abort then deletion. Late control fulfillment and rejection are observed so they cannot leak a scratch or an unhandled rejection. Candidate failures retain provider, control, validation, and deletion failures in deterministic candidate and stage order. Surfaced capsule lifecycle errors contain only the source session ID, candidate index, stage, timeout/rejection kind, fixed validation categories, and a range-validated HTTP status; raw provider/control/model messages, causes, bodies, names, codes, and response output are discarded.
- Malformed qualifying data URIs and non-vision configured models fail before scratch creation. Provider rejection, missing substantive visual coverage, projection mismatch, and every other media validation failure occur before backup/source mutation/success stats. No media path falls back to another model or provider.
- If a backup exists, it is used for recovery.
- Cache-read diagnostics must not expose local filesystem or session paths. Integrity diagnostics may retain path-free validation detail.
- During `/magic-compact`, malformed, ambiguous, dangling, or active incomplete native checkpoint state, and behavior-affecting drift detected by pre-write revalidation, fail before summary, boundary, or pruning writes. An older incomplete or ambiguous marker may remain only when its complete ambiguous or incomplete artifact set lies wholly before a later valid checkpoint marker and is inside that checkpoint's frozen prefix.
- After owned capsule and boundary insertion, Magic Compact reloads the full source and requires the original snapshot plus exactly those insertions. Any unexpected added, missing, changed, or reordered message or part rolls back through the backup before a planned prune mutation, omission commit, stats write, or source metadata update.
- Preserve-both recovery remains reserved for pre-write source drift detected after backup creation and final actual-versus-projected token mismatch after source writes. Final mismatch preserves the partially mutated source and backup and records no successful stats increment.
- Capsules preserve operational continuity through validated refs and current structured state. The model response has exactly one substantive text part containing plain JSON with exact canonical keys and no BOM, surrounding content, second value, or duplicate object key at any depth. Status is one of `completed`, `partial`, `blocked`, or `analysis-only`; the host-rendered outcome is the canonical human conclusion and must be a trimmed control-free substantive result rather than a status-only/meta non-result. Process is readable nonempty Markdown, cannot inject host `Outcome:`/`Process:` framing, and may avoid repeating the conclusion. `finalResponse: "preserve"` requires substantive non-synthetic text in the true final assistant message, keeps it exact and in place, and cannot duplicate a meaningful full response after conservative Unicode/Markdown/whitespace normalization. `finalResponse: "summarize"` replaces eligible assistant text.
- Final visible validation runs over the host-framed text. It rejects collected sufficiently identifier-like source message, part, session, assistant-parent, and tool-call IDs; evidence/ref/trace/omission scaffolding and counters; and imperative instructions to call retrieval tools or fetch omitted content for understanding. Declarative project facts that optional retrieval exists for forensic support remain allowed.
- Required running/error tool refs, assistant error refs, verification/not-run/current-failure refs, and narrow allowlisted Hive/task terminal failure refs must be present in `unresolvedRefs`. `partial` and `blocked` require unresolved refs and human unresolved/next content. `completed` and `analysis-only` cannot carry unresolved refs. Broad lexical status parsing over arbitrary assistant prose is not a correctness source.
- Semantic observations are reduced in source order into one current unresolved map. Verification parsing recognizes passed, failed/error, skipped, todo, cancelled, and not-run groups. Positive passed counts with zero failures are success even with skips. Zero executed counts or skipped/todo/cancelled-only results are not-run and cannot resolve a prior failure. Strong nonzero domain failures remain unresolved even when exit metadata is zero.

## Stats

- Track net tokens physically pruned, inline-image tokens projected out per model request, their separate cached-read savings, and estimated money saved per conversation. Existing version-1 stats without media fields remain valid and read as zero media savings. Before, projected-after, and actual-after model-facing counts use the same pure media projection plus local `gpt-tokenizer` canonical active-content method: model-facing synthetic parts are included and ignored reporting notices are excluded. Compaction and trim compute the exact pre-notice active result once, persist savings on that basis, inject an ignored notice that explicitly says it is excluded, and require the final actual active count to equal the projection. There is no self-referential fixed point. Every notice distinguishes this estimate from provider context-window usage. OpenCode's context meter is a provider usage snapshot and can remain stale after in-place compaction until a later assistant response refreshes it. Magic Compact never fabricates an after-provider count or mutates provider token metadata.
